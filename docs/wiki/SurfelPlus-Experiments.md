# SurfelPlus 기반 표본 배분·접촉 차폐 실험

UE6 브랜치의 [구현 커밋 `608f865`](https://github.com/mazelines/UE6-PRT-GI/commit/608f865f360ccc3dfc90496e5bc92c78b7b2f47b)을 기준으로 설명합니다. [SurfelPlus](https://wangruipeng.com/SurfelPlus/)에서 검토한 표본 배분·저해상도 계산 아이디어를 이 플러그인의 **정적 PRT 사전 계산과 프로브 보간**에 맞춰 적용했습니다. SurfelPlus의 전체 렌더러를 이식한 것은 아닙니다.

기본값은 **6회 바운스, 캡처 표본당 전송 경로 1개, 적응형 배분 끔, 반해상도 접촉 차폐 끔**을 유지합니다. 사전 계산 캐시는 Git에 포함하지 않으므로 처음 프로젝트를 열면 각 볼륨에서 **Build Precomputation**을 실행해야 합니다.

## 구현 범위

기존 구조는 캡처한 표면과 정적 지오메트리에서 전송을 사전 계산하고, 현재 방향광으로 GPU 재조명한 SH 계수를 화면에서 보간합니다. 이번 변경은 세 부분을 다룹니다.

| 기능 | 적용 단계 | 다시 사전 계산해야 하는가? |
|---|---|---|
| 프로브 기여 수·유효 수·가중치 집중도 진단 | 화면의 프로브 보간 | 아니요 |
| 다중 경로와 적응형 표본 배분 | 오프라인 전송 사전 계산 | 예 |
| 반해상도 접촉 차폐와 경계 복원 | 매 프레임의 짧은 거리 접촉 차폐 | 아니요 |

시간 이력 필터, 런타임 Surfel 생성·이동, 정반사 GI는 추가하지 않았습니다. 움직이는 차폐물, 하늘광·발광 전송도 기존 지원 범위에 포함되지 않습니다. 사전 계산된 다중 바운스 경로를 매 프레임 다시 추적하지 않습니다.

## 프로브 기여도 진단

간접광만 표시하고 기본 노출 설정에서 다음 모드를 하나씩 비교합니다. HDR 계측용 `r.EyeAdaptation.PreExposureOverride 1`을 사용 중이었다면 먼저 0으로 복원하세요.

```text
r.EyeAdaptation.PreExposureOverride 0
r.PRTGI.IndirectOnly 1
r.PRTGI.Debug 5
```

| 명령 | 표시하는 값 |
|---|---|
| `r.PRTGI.Debug 5` | 실제 기여 프로브 수. 16으로 나눈 값을 색으로 표시하며 16 이상은 녹색 |
| `r.PRTGI.Debug 6` | 유효 프로브 수 `(Σw)² / Σ(w²)`. 소수 프로브에 가중치가 집중되면 낮아짐. 16 이상은 녹색 |
| `r.PRTGI.Debug 7` | `1 − 최대 정규화 가중치`. 한 프로브에 집중되면 빨강, 분산되면 녹색 |

값은 볼륨 경계 혼합 전 선택된 볼륨 기준입니다. 기존 전역 trilinear 경로는 자홍색으로 구분합니다. 진단 색상을 장면의 물리적 광량처럼 사전 노출 배율로 줄이지 않도록 수정해 밝은 장면에서도 분포를 확인할 수 있게 했습니다. 진단이 끝나면 다음 값을 복원합니다.

```text
r.PRTGI.Debug 0
r.PRTGI.IndirectOnly 0
```

곡면의 원형 경계를 완화했던 `HemisphereTransition=0.2`는 그대로 유지합니다. 이번 진단은 남은 얼룩이 프로브 기여도 집중과 연관되는지 조사하기 위한 도구이며, 자체적으로 조명 품질을 바꾸지는 않습니다. 이전 수정은 [곡면 보간 개선](https://github.com/mazelines/UE6-PRT-GI/wiki/Curved-Surface-Interpolation)을 참고하세요.

## 적응형 전송 표본 배분

각 `PRTProbeVolume`의 **PRT → Build**에서 설정합니다.

| 항목 | 기본값 | 의미 |
|---|---:|---|
| Transport Paths Per Sample | 1 | 캡처 표본당 실제 전송 경로 수, 범위 1~16. 적응형 모드에서는 각 프로브의 평균 예산 |
| Adaptive Transport Sampling | false | 경로 수가 2 이상일 때 예비 표본 기반 배분 사용 |

균등 모드는 각 캡처 표본에서 지정한 수의 경로를 추적합니다. 적응형 모드는 별도의 예비 경로 2개로 삼각형·바운스별 확산 응답의 변동을 추정하고 SH 가중치 크기를 반영해 실제 경로 예산을 배분합니다. 현재 태양의 방향·밝기나 카메라에 맞춰 예산을 정하지 않습니다.

각 캡처 표본에는 최소 1개, 최대 평균 예산의 4배까지 경로를 배분하며, 프로브별 실제 경로 총수는 고정합니다. 예비 경로는 최종 전송 계수에 포함하지 않습니다. 실제 경로의 기여는 해당 표본에 배분된 경로 수로 나눠 누적합니다. 이는 광원과 무관한 대리 지표를 사용하는 실험으로, 조명 오차나 분산 감소를 보장하는 추정기가 아닙니다.

**균등 4개**와 **적응형 2개＋예비 2개**는 시작 경로 수가 같지만, 경로 길이·조기 종료·재질 조회 비용이 달라 실행 시간이 같지는 않습니다. 예비 경로 비용까지 포함해 비교해야 합니다.

설정을 바꾸면 **Build Precomputation**을 실행하세요. v8 캐시는 표본 설정과 예비·실제 경로 수를 저장하고, 요청 설정과 맞지 않는 전송 캐시를 사용하지 않습니다. 기존 v3~v7 캐시는 균등 1개 설정에서 계속 읽습니다. v3~v6의 최대 반사 횟수는 기존처럼 4회이며, v7 이상은 최대 12회입니다. 유효한 지오메트리 캐시는 재사용할 수 있습니다.

설정 변경 직후 빌드 버튼을 눌렀을 때 요청이 사라지는 문제도 수정했습니다. 전송 설정을 무효화할 때 명시적인 대기 요청을 보존하고, 평소의 2초 검증 주기를 기다리지 않고 캐시를 먼저 검증합니다.

## 반해상도 접촉 차폐

```text
r.PRTGI.ContactHalfResolution 1
```

접촉 차폐가 활성화된 상태에서 가로·세로 절반 해상도로 광선을 추적합니다. 결과를 전체 해상도로 복원할 때 주변 표본의 법선과 양쪽 접평면 거리를 검사합니다. 얇은 물체·실루엣·불충분한 표본 영역은 전체 해상도 계산으로 돌아갑니다. 시간 이력은 사용하지 않습니다.

이 옵션은 **접촉 차폐만** 저해상도로 계산합니다. SH 프로브 보간과 전체 GI를 모두 반해상도로 바꾸는 기능은 아닙니다. 접촉 표본이 0이면 해당 패스는 실행되지 않습니다. 호스트 프로젝트는 `r.PRTGI.ContactSamples=8`을 사용하며 플러그인 자체 기본값은 0입니다.

비교 후 기본 경로로 돌아가려면 다음 명령을 실행합니다.

```text
r.PRTGI.ContactHalfResolution 0
```

## 로컬 측정 결과

2026-10-15, UE6 Showcase, RTX 4090에서 측정했습니다. 다음 수치는 원본 SurfelPlus와의 성능 비교가 아닙니다.

### 접촉 차폐

6회 바운스, 접촉 표본 8개, 가시성 모드 1, 반구 전환 폭 0.2, 간접광 전용 출력 조건입니다.

| 시점 | 전체 해상도 PRT 패스 | 반해상도 PRT 패스 합계 | 전체 해상도 대비 HDR 상대 RMSE |
|---|---:|---:|---:|
| 넓은 화면 | 3.479 ms | 3.454 ms | 3.37% |
| 구체 근접 | 3.800 ms | 2.609 ms | 6.04% |

GPU 수치는 모드를 번갈아 5회 측정한 중앙값이며, 반해상도 열은 접촉 패스와 적용 패스의 합계입니다. TSR 입력은 1671×577, 출력은 1853×639입니다. 첫 넓은 화면 반해상도 표본의 9.196 ms 이상값도 원시 기록에 남겼습니다. 넓은 시점에서 유의미한 성능 이득을 확인하지 못했으며 통계적 유의성을 검증한 결과는 아닙니다.

HDR 비교는 설정당 1853×639 `PreTonemapHDRColor` 한 장을 사용했습니다. 기준은 전체 해상도 8광선 접촉 차폐이며 **Path Tracing이 아닙니다.** RMSE는 복원·샘플링 차이를 나타내므로 정확도가 개선됐다는 뜻이 아닙니다. 경계가 많은 시점에서는 비용이 늘 수도 있어 기본값을 0으로 유지합니다.

### 전송 표본 배분

ColorBox 안의 별도 검증 볼륨에서 프로브 8개, 캡처 표본 741개, 캡처 해상도 4를 사용했습니다. 균등 16개를 유한 기준으로 삼아 6회 바운스 SH9 RGB 계수를 비교했습니다.

| 설정 | 실제 시작 경로 | 예비 시작 경로 | 기준 대비 계수 상대 L2 차이 |
|---|---:|---:|---:|
| 균등 1개 | 741 | 0 | 8.89% |
| 균등 4개 | 2,964 | 0 | 2.87% |
| 적응형 2개＋예비 2개 | 1,482 | 1,482 | 4.69% |
| 균등 16개 기준 | 11,856 | 0 | — |

이 장면에서는 같은 시작 경로 수를 쓰는 균등 4개가 적응형 방식보다 기준에 가까웠습니다. 광원 가림을 끈 4개 방향광 입력·고정 난수열의 작은 검증이며, 균등 4개와 적응형 결과는 기준 경로 일부를 공유합니다. 기준도 유한 표본이므로 참값이 아니고, 여러 난수열에 대한 분산이나 같은 실행 시간에서의 우위를 검증하지 않았습니다. 따라서 적응형 배분은 기본 비활성화 상태로 남깁니다.

## 빌드·검증과 자료

Win64 Development Editor 빌드와 PRTGI 자동화 테스트 15개가 통과했습니다. PIE 테스트 중에는 기존 호스트 CommonUI의 뷰포트 클라이언트 경고를 분리하기 위해 `CommonUI.Debug.CheckGameViewportClientValid=0`을 적용했고, 이후 1로 복원했습니다. 설정 변경과 빌드 요청을 같은 호출에서 수행하는 추가 검증도 통과했습니다.

기존 여섯 볼륨의 캐시는 유지했고 임시 검증 볼륨은 제거했습니다. 레벨을 저장하지 않았으며, 테스트 후 기존 여섯 볼륨이 모두 6회 PRT GI로 활성화된 것을 확인했습니다.
